# 게임 모드 (MODES)

기획은 `PLANNING.md`의 "모드", 화면은 `ROUTES.md`, 데이터는 `DATA_MODEL.md`, 미션 부여는 `MISSION_ASSIGN.md`, 결과 공개는 `RESULT_REVEAL.md` 참고.

## 한눈에 보기

- 모드는 **방을 만들 때 고르고**, 친구를 초대하기 전에 정해진다. 이후에는 바꿀 수 없다.
- 모드는 `Room.settings.mode`에 저장된다. 모드별 기본값과 고를 수 있는 값은 `apps/web/src/lib/modes.ts` 한 곳에서 정의하고, 화면은 그 정의만 읽는다. (화면에 모드별 `if`를 두지 않는다)
- 이 문서의 범위는 **모드 선택, 저장, 모드별 설정 제약, 표시**까지다. 모드별 실제 플레이(아래 "한계와 열린 질문")는 아직 구현하지 않았다.

## 흐름

```
방만들기(/room/new): 1단계 모드 선택 → 2단계 닉네임·동물 선택 → 방 만들기 → 대기실
대기실: 친구 초대(1인모드는 초대 없음) → 게임 시작
게임 설정: 모드가 허용하는 값만 방장이 고름 → 설정 완료 → 미션지정
```

## 모드별 설정

`or`가 있는 칸은 **앞쪽이 기본값**이고 뒤쪽도 고를 수 있다는 뜻이다.

| 모드 | 미션은 누가 정하나 | 모두 같은 미션인지 | 미션 공개 | 수행 현황 | 추가 설정 | 결과 공개 시각 | 초대 |
|---|---|---|---|---|---|---|---|
| 매일매일 `daily` | 앱 or 유저 | 같음 (고정) | 전체 공개 (고정) | 제출 여부 | 진행 일수 | 진행 일수가 있으면 B, 없으면 A | ✅ |
| 일회성 `oneshot` | 유저 or 앱 | 각자 다름 or 같음 | 본인만 확인 or 전체 공개 | 제출 여부 | - | B | ✅ |
| 선착순 `race` | 앱 (고정) | 같음 (고정) | 전체 공개 (고정) | 제출 여부 | - | A | ✅ |
| 1인모드 `solo` | 앱 (고정) | 해당 없음 | 해당 없음 | 없음 | - | A | ❌ |
| 무한미션 `endless` | 앱 (고정) | 같음 or 각자 다름 | 전체 공개 or 본인만 확인 | 개수만 공개 | 제한 시간 | A | ✅ |

- "미션 공개"는 모두 같은 미션이면 묻지 않고 전체 공개로 정해진다. (아래 "같은 미션이면 전체 공개")
- "해당 없음"은 게임 설정 화면에서 숨기고, 기본값(`scope = different`, `visibility = private`)만 저장한다.
- 매일매일의 "앱 or 유저"는 방 단위 설정이다. 날짜별로 바꾸는 것은 매일매일 플레이를 구현할 때 다룬다.
- "수행 현황"은 정의(`progress`)만 있고, 개수 공개 같은 화면은 해당 모드 플레이를 구현할 때 만든다.

## 설정을 정의하는 방식 (`lib/modes.ts`)

| 값 | 의미 |
|---|---|
| `Choice.default` | 방을 만들 때 저장되는 값 |
| `Choice.options` | 고를 수 있는 값. **2개 이상이면 방장이 선택**, **1개면 고정**(읽기 전용, "이 모드에서는 고정이에요."), **0개면 해당 없음**(화면에서 숨김) |
| `invite` | 친구 초대가 필요한 모드인가. `false`면 대기실에서 초대 영역을 숨긴다 |
| `resultAt` | 결과 공개 시각 정책(`none` 또는 `choice`). 현재 설정에 따라 달라질 수 있어 함수다 |

### 추가 설정

| 설정 | 모드 | 기본 | 범위 (단위) | 정하지 않기 |
|---|---|---|---|---|
| `durationDays` 진행 일수 | 매일매일 | 7일 | 2~30일 (1일) | 가능. "기간 없이 계속하기"를 고르면 `null`로 저장된다 |
| `timeLimitSec` 제한 시간 | 무한미션 | 180초 | 60~600초 (30초) | 불가 |

값은 지금은 저장만 하고, 실제로 쓰는 것은 해당 모드 플레이를 구현할 때다. 범위는 화면(+/- 버튼)에서만 지켜지고 규칙이 검사하지는 않는다.

## 같은 미션이면 전체 공개

- 게임 설정에서 "모두 같은 미션"을 고르면 "미션을 미리 공개할까요?" 박스는 보이지 않고, `visibility`는 `public`으로 함께 저장된다. (`scopePatch`)
- "각자 다른 미션"으로 돌아오면 `visibility`는 **모드의 기본값**으로 되돌아간다. (일회성은 `private`, 무한미션은 `public`)
- 같은 미션이면서 `public`이 아닌 예전 방은, 방장이 게임 설정 화면을 열면 자동으로 `public`으로 바로잡는다.
- 설정 박스 순서: 미션은 누가 정하나요? → 모두 같은 미션인가요? → (각자 다른 미션일 때만) 미션을 미리 공개할까요?

## 결과 공개 시각 정책

| 정책 | 뜻 | 게임 설정 화면 |
|---|---|---|
| **A** `none` | 결과 공개 시각을 정하지 않는다. 제한 시간이 있으면 제한 시간이 끝날 때 공개하고, 없으면 방장이 직접 공개한다 | 입력 없이 안내 문구만 보인다 |
| **B** `choice` | 방장이 시각을 정할지 말지 고른다 | "시각 정하기 / 정하지 않기" 선택. 기본은 "정하지 않기" |

- 시각을 정하지 않으면 `Room.resultAt = null`이다. 이때 결과는 시각으로는 열리지 않고, 방장이 미션 진행 화면에서 **지금 결과 공개하기**를 눌러야 열린다. (`RESULT_REVEAL.md`)
- B에서 시각을 정하기로 했다면 지금보다 뒤여야 **설정 완료**를 누를 수 있다. 정하지 않기로 했다면 시각 없이 완료된다.
- 매일매일은 진행 일수에 따라 정책이 바뀐다. "기간 없이 계속하기"를 고르면 B에서 A로 바뀌고, 이미 정해 둔 결과 시각은 자동으로 비워진다.
- A 모드의 방에 결과 시각이 남아 있으면(예전 방) 방장이 게임 설정 화면을 열 때 비워진다.
- "제한 시간이 끝나면 공개"는 안내 문구만 있고, 시간이 끝나면 결과를 여는 동작은 무한미션 플레이를 구현할 때 만든다.

## 보안 규칙 (`firestore.rules`)

| 대상 | 규칙 |
|---|---|
| 방 만들기 | `settings.mode`가 `daily` `oneshot` `race` `solo` `endless` 중 하나여야 한다. |
| 방 수정 | 방장만, `hostId`와 `settings.mode`는 바꿀 수 없다. (`settings`의 다른 필드는 방장이 바꿀 수 있다) |

## 배포 전 확인

`firestore.rules`를 다시 게시한 뒤 개발용 프로젝트에서 확인한다. 방법은 `SECURITY.md`의 "배포 전 확인"과 같다. (일반 창·시크릿 창, 규칙 플레이그라운드)

| # | 상황 | 기대 결과 |
|---|---|---|
| Mo1 | 방을 만들 때 `settings.mode`를 5가지가 아닌 값으로 저장 | 거부 |
| Mo2 | 방장이 `settings.mode`를 다른 모드로 수정 | 거부 |
| Mo3 | 방장이 `settings.assigner`, `settings.scope` 등 다른 필드 수정 | 허용 |
| Mo4 | 방장이 아닌 사용자가 `settings` 수정 | 거부 |
| Mo5 | 방장이 `resultAt`을 `null`로 수정 | 허용 |
| Mo6 | 모드를 고르고 방 만들기 | 허용 (대기실에 모드 배지가 보인다) |

## 한계와 열린 질문

- **서버가 강제하는 것은 모드 값과 모드 변경 금지뿐이다.** 모드별 고정 항목(예: 선착순은 같은 미션 고정)과 값의 범위는 화면에서만 막는다. 친구끼리 쓰는 앱이라 허용하는 범위로 보았고, 필요하면 규칙에 모드별 표를 옮겨 적거나 Cloud Function으로 옮긴다.
- **모드별 플레이는 아직 없다.** 어떤 모드를 골라도 진행은 일회성 흐름(미션지정 → 미션 진행 → 결과)과 같다.

| 모드 | 아직 없는 것 |
|---|---|
| 매일매일 | 날짜별 라운드와 매일 미션 배정, 진행 일수 사용. 배정·제출 문서 ID(`a-{uid}`, `s-a-{uid}`)가 하루치만 가능한 구조라 바꿔야 한다 |
| 선착순 | 먼저 한 명만 살아남는 규칙과 탈락 처리 (`DATA_MODEL.md` 열린 질문 2) |
| 1인모드 | 혼자 하는 전용 흐름과 캐릭터 성장. 결과/시상식이 투표할 친구를 전제로 해서 혼자서는 막힐 수 있다 |
| 무한미션 | 미션을 깰 때마다 다음 미션이 나오는 연결(`order`), 제한 시간 타이머와 시간 종료 시 결과 공개, 수행 개수 공개 |

- 결과/시상식(`/result`)은 모드와 무관하게 "웃긴 미션·어려운 미션 투표 + 가장 빠른 사람" 구조 하나뿐이다.
- 일회성 외의 모드에서 사진 인증 안내(`PhotoNotice`)가 그대로 쓰이는지 확인이 필요하다.
