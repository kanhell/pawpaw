# 제출 현황과 결과 먼저 공개 (RESULT_REVEAL)

보안 설계는 `SECURITY.md`, 데이터는 `DATA_MODEL.md`, 화면은 `ROUTES.md`, 미션 부여는 `MISSION_ASSIGN.md` 참고.
이 문서는 `SECURITY.md`의 접근 규칙(사진은 결과 공개 전까지 본인만)을 **바꾸지 않고**, 아래 두 가지를 더한다.

1. 방장을 포함한 모든 멤버가 서로 **제출했는지만** 알 수 있다.
2. 방장은 결과 시각(`resultAt`)이 되기 전에도 결과를 **먼저 공개**할 수 있다.

## 1. 제출 현황 (제출 여부만 보인다)

| 보이는 것 | 보이지 않는 것 |
|---|---|
| 멤버별 제출 여부 (제출함 / 아직이에요, 글자 색으로 구분), 제출한 인원 수 | 사진, 사진 경로, 제출 시각, 어떤 미션을 받았는지 |

### 저장

- `rooms/{roomId}/members/{uid}`에 `submitted: true` 하나만 추가한다. (`Player.submitted`)
- 멤버 문서는 같은 방 멤버 모두가 읽을 수 있으므로, 이 표시로 서로의 제출 여부를 안다.
- 제출 문서(`submissions`)와 사진(Cloud Storage)의 **읽기 규칙은 바꾸지 않았다.** 결과 공개 전에는 여전히 본인만 읽을 수 있다.

### 언제 표시하나

- 사진 제출이 끝나 내 제출 문서가 보이는데 내 `submitted`가 아직 없으면 미션 진행 화면이 자동으로 `markSubmitted`를 호출한다. (`apps/web/src/lib/firebase/roomRepo.ts`)
- 표시를 남기지 못했더라도(네트워크 등) 화면을 다시 열면 다시 시도한다. 이미 제출한 사람이 기능 추가 전에 낸 사진도 같은 방식으로 채워진다.
- 사진을 교체해도 표시는 그대로이고, 표시는 `true`에서 되돌릴 수 없다.

### 규칙 (`firestore.rules`의 `validMemberUpdate`)

- 본인 문서에서만, `animal` · `assignmentDone` · `submitted` 세 키만 바꿀 수 있다.
- `submitted`는 `true`로만 바꿀 수 있고, **내 제출 문서(`s-a-{내 uid}`)가 이미 있을 때만** 허용된다. 제출하지 않고 표시만 남길 수는 없다.

## 2. 결과 먼저 공개

- 미션 진행 화면에서 방장에게만 **지금 결과 공개하기**가 보인다. 누르면 확인 문구(아직 제출하지 않은 인원 수 포함)가 나오고, **공개하기**를 눌러야 진행된다.
- 공개하면 방 문서를 이렇게 바꾼다. (`revealResultsNow`)

| 필드 | 값 | 이유 |
|---|---|---|
| `resultAt` | 서버 시각(지금) | 규칙의 `resultsOpen`이 곧바로 참이 되어 같은 방 멤버가 사진을 볼 수 있다. |
| `deadlineAt` | 서버 시각(지금) | 규칙의 `beforeDeadline`이 거짓이 되어 더 이상 제출·교체할 수 없다. |
| `status` | `finished` | 화면이 정해 둔 시각을 기다리지 않고 바로 결과 보기로 넘어가게 한다. |
| `phase` | `null` | `playing`이 아니므로 비운다. |

- 되돌릴 수 없다. 공개 이후에는 같은 방 멤버가 모두의 사진을 볼 수 있고, 제출하지 않은 사람은 제출할 수 없다.
- 방장만 할 수 있다. (기존 `rooms` 문서 수정 규칙이 방장만 허용한다. 규칙 변경 없음)
- 정해 둔 시각이 지나서 자연히 열린 경우에는 `status`가 바뀌지 않는다. 화면은 `status = finished`이거나 `resultAt`이 지났으면 결과 보기 링크를 보여준다.

## 3. 미션 구경 → 투표

- 방 화면의 '미션이 종료되었어요' 팝업에서 **구경하러 가기**를 누르면 결과 화면으로 간다.
- 결과 화면에 들어오면 내 멤버 문서에 `resultEntered = true`를 남긴다. (규칙: true로만, 결과가 열린 뒤에만)
- 모두 들어오기 전에는 대기 화면(n / 전체 명)이 보이고, 모두 들어와야 방장이 **첫 미션 보기**를 누를 수 있다. 누르면 `showcaseIndex = 0`.
- **미션 구경**: 사진을 낸 친구(나 포함)를 한 명씩, 받은 미션과 사진으로 보여준다.
- 방장만 **다음 친구** / 마지막에는 **투표 시작하기**를 누를 수 있다. 누르면 방 문서의 `showcaseIndex`가 1 늘고, 모두의 화면이 실시간으로 따라 넘어간다.
- 구경 중에는 지금 보는 친구에게 **붐따**(별로예요)를 누를 수 있다. 한 사람에게 한 번만, 자기 자신에게는 못 누른다. 누른 수만 모두에게 실시간으로 보이고, 누가 눌렀는지는 화면에 보여주지 않는다. 저장 위치: `rooms/{roomId}/boomdowns/{받는사람uid}_{누른사람uid}`
- **인정 투표**: 붐따가 그 친구를 뺀 멤버의 30% 이상(올림)이면, 본인을 포함한 모두에게 "이 미션을 인정할까요?" 시트가 아래에서 올라온다. (`apps/web/src/lib/judgment.ts`)
  - 본인 포함 전체 멤버 중 불인정이 과반이면 **미션 실패**, 인정이 절반 이상이면 **인정**. 결과 화면에 들어온 사람이 모두 투표했는데도 갈리지 않으면 인정으로 본다.
  - 판정이 나기 전에는 방장이 다음 친구로 넘길 수 없다.
  - 미션 실패한 친구는 웃긴/어려운 미션 투표 후보와 '가장 빠른 미션'에서 빠진다.
  - 저장 위치: `rooms/{roomId}/judgments/{받는사람uid}_{투표한사람uid}` (`accept: true/false`). 30% 조건은 규칙이 셀 수 없어 화면에서만 막는다.
- `showcaseIndex`가 사진을 낸 친구 수에 닿으면 투표가 시작된다.

## 4. 시상식 (다 같이)

- 투표를 마치면 대기 화면이 보인다. **결과 공개**는 방장만 누를 수 있고, 아직 투표하지 않은 사람이 있으면 "그래도 공개할까요?"를 한 번 묻는다.
- 누르면 방 문서의 `awardIndex = 0`이 되고, 모두 최신 투표를 다시 불러온 뒤 같은 상을 함께 본다. 방장이 **다음**을 누르면 1씩 늘고 모두 따라 넘어간다.
- `awardIndex`가 상 개수에 닿으면 모두 결과 카드로 간다. **발표 다시 보기**는 각자 따로 본다.
- 투표를 아직 하는 중인 사람은 투표를 마친 뒤 지금 진행 중인 상부터 따라간다. 투표 화면에서도 후보마다 사진과 받은 미션이 보인다.
- 결과가 열린 뒤에는 같은 방 멤버가 모든 배정(미션)과 사진을 읽을 수 있다. (기존 규칙 그대로)
- 방장이 결과 화면에 없거나, 한 명이라도 결과 화면에 들어오지 않으면 구경이 시작되지 않는다.

## 한계와 열린 질문

- 제출 표시는 본인 기기가 남기는 값이다. 규칙이 "내 제출 문서가 있을 때만"으로 막지만, 사진을 제출한 뒤 표시를 남기지 못하면 다른 사람 화면에는 한동안 '아직이에요'로 보인다.
- 결과 공개는 되돌릴 수 없다. 실수로 눌렀을 때를 위한 취소 기능은 없고, 확인 문구 한 번으로 막는다.
- 먼저 공개해도 Cloud Storage 규칙에는 마감 검사가 없다. 마감 이후에도 본인 사진 파일을 같은 경로에 다시 올릴 수는 있지만, 제출 문서를 만들거나 고칠 수 없어 화면에는 반영되지 않는다. (`SECURITY.md` 열린 질문과 함께 정리 필요)
- `status = finished`는 지금은 방장의 공개로만 바뀐다. 시각이 지나서 자동으로 `finished`가 되는 것은 서버(Cloud Function)가 생긴 뒤의 일이다. (`SECURITY.md` "서버가 맡을 일")
- 결과/시상식 화면(`/room/:roomId/result`)은 아직 목업 데이터를 쓴다. 이번 작업은 그 화면으로 가는 링크와 공개 시점까지만 다룬다.
- 시각이 지나기 전에 공개한 경우 `resultAt`이 원래 예정 시각에서 지금으로 덮어써진다. 원래 시각은 남지 않는다.
