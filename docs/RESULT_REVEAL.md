# 제출 현황과 결과 먼저 공개 (RESULT_REVEAL)

보안 설계는 `SECURITY.md`, 데이터는 `DATA_MODEL.md`, 화면은 `ROUTES.md`, 미션 부여는 `MISSION_ASSIGN.md`, 모드는 `MODES.md` 참고.
이 문서는 `SECURITY.md`의 접근 규칙(사진은 결과 공개 전까지 본인만)을 **바꾸지 않고**, 아래 두 가지를 더한다.

1. 방장을 포함한 모든 멤버가 서로 **제출했는지만** 알 수 있다.
2. 방장은 결과 시각(`resultAt`)이 되기 전에도 결과를 **먼저 공개**할 수 있다. 결과 공개 시각을 정하지 않은 방에서는 이것이 결과를 여는 방법이다.

## 1. 제출 현황 (제출 여부만 보인다)

| 보이는 것 | 보이지 않는 것 |
|---|---|
| 멤버별 제출 여부 (✅ 제출함 / ⏳ 아직이에요), 제출한 인원 수 | 사진, 사진 경로, 제출 시각, 어떤 미션을 받았는지 |

### 저장

- `rooms/{roomId}/members/{uid}`에 `submitted: true` 하나만 추가한다. (`Player.submitted`)
- 멤버 문서는 같은 방 멤버 모두가 읽을 수 있으므로, 이 표시로 서로의 제출 여부를 안다.
- 제출 문서(`submissions`)와 사진(Cloud Storage)의 **읽기 규칙은 바꾸지 않았다.** 결과 공개 전에는 여전히 본인만 읽을 수 있다.

### 언제 표시하나

- 사진 제출이 끝나 내 제출 문서가 보이는데 내 `submitted`가 아직 없으면 미션 진행 화면이 자동으로 `markSubmitted`를 호출한다. (`apps/web/src/lib/firebase/roomRepo.ts`)
- 표시를 남기지 못했더라도(네트워크 등) 화면을 다시 열면 다시 시도한다. 이미 제출한 사람이 기능 추가 전에 낸 사진도 같은 방식으로 채워진다.
- 사진을 교체해도 표시는 그대로이고, 표시는 `true`에서 되돌릴 수 없다.

### 규칙 (`firestore.rules`의 `validMemberUpdate`)

- 본인 문서에서만, `animal` · `assignmentDone` · `submitted` 세 키만 바꿀 수 있다.
- `submitted`는 `true`로만 바꿀 수 있고, **내 제출 문서(`s-a-{내 uid}`)가 이미 있을 때만** 허용된다. 제출하지 않고 표시만 남길 수는 없다.

## 2. 결과 먼저 공개

- 미션 진행 화면에서 방장에게만 **지금 결과 공개하기**가 보인다. 누르면 확인 문구(아직 제출하지 않은 인원 수 포함)가 나오고, **공개하기**를 눌러야 진행된다.
- 공개하면 방 문서를 이렇게 바꾼다. (`revealResultsNow`)

| 필드 | 값 | 이유 |
|---|---|---|
| `resultAt` | 서버 시각(지금) | 규칙의 `resultsOpen`이 곧바로 참이 되어 같은 방 멤버가 사진을 볼 수 있다. |
| `deadlineAt` | 서버 시각(지금) | 규칙의 `beforeDeadline`이 거짓이 되어 더 이상 제출·교체할 수 없다. |
| `status` | `finished` | 화면이 정해 둔 시각을 기다리지 않고 바로 결과 보기로 넘어가게 한다. |
| `phase` | `null` | `playing`이 아니므로 비운다. |

- 되돌릴 수 없다. 공개 이후에는 같은 방 멤버가 모두의 사진을 볼 수 있고, 제출하지 않은 사람은 제출할 수 없다.
- 방장만 할 수 있다. (기존 `rooms` 문서 수정 규칙이 방장만 허용한다. 규칙 변경 없음)
- 정해 둔 시각이 지나서 자연히 열린 경우에는 `status`가 바뀌지 않는다. 화면은 `status = finished`이거나 `resultAt`이 지났으면 결과 보기 링크를 보여준다.

### 결과 공개 시각을 정하지 않은 방 (`resultAt = null`)

- 결과 공개 시각은 모드와 방장의 선택에 따라 정하지 않을 수 있다. (`MODES.md`의 "결과 공개 시각 정책")
- `resultAt`이 비어 있으면 규칙의 `resultsOpen`이 거짓이라, **방장이 위의 방법으로 공개하기 전에는 사진과 시상식이 열리지 않는다.**
- 미션 진행 화면의 방장 안내는 "결과 공개 시각을 정하지 않았어요. 준비되면 직접 공개해 주세요."로 바뀐다.
- 제한 시간이 있는 모드(무한미션)는 제한 시간이 끝날 때 공개하기로 했지만, 시간이 끝나면 자동으로 여는 동작은 아직 없다. 지금은 방장이 직접 공개한다.

## 한계와 열린 질문

- 제출 표시는 본인 기기가 남기는 값이다. 규칙이 "내 제출 문서가 있을 때만"으로 막지만, 사진을 제출한 뒤 표시를 남기지 못하면 다른 사람 화면에는 한동안 ⏳로 보인다.
- 결과 공개는 되돌릴 수 없다. 실수로 눌렀을 때를 위한 취소 기능은 없고, 확인 문구 한 번으로 막는다.
- 먼저 공개해도 Cloud Storage 규칙에는 마감 검사가 없다. 마감 이후에도 본인 사진 파일을 같은 경로에 다시 올릴 수는 있지만, 제출 문서를 만들거나 고칠 수 없어 화면에는 반영되지 않는다. (`SECURITY.md` 열린 질문과 함께 정리 필요)
- `status = finished`는 지금은 방장의 공개로만 바뀐다. 시각이 지나서 자동으로 `finished`가 되는 것은 서버(Cloud Function)가 생긴 뒤의 일이다. (`SECURITY.md` "서버가 맡을 일") 제한 시간이 끝날 때 결과를 여는 것도 같은 서버 작업이 필요하다.
- 결과/시상식 화면(`/room/:roomId/result`)은 모드와 상관없이 같은 구조(웃긴 미션·어려운 미션 투표, 가장 빠른 사람)를 쓴다. 이 화면으로 가는 링크와 공개 시점까지만 이 문서가 다룬다.
- 시각이 지나기 전에 공개한 경우 `resultAt`이 원래 예정 시각에서 지금으로 덮어써진다. 원래 시각은 남지 않는다.
