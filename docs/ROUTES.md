# 화면 라우팅 (ROUTES)

기획 흐름은 `PLANNING.md`, 데이터는 `DATA_MODEL.md` 참고.
표의 **상태**: `확정` = 코드(`packages/shared/src/routes.ts`)와 페이지가 있음 / `제안` = 기획 반영을 위해 추가를 제안한 화면, 확인 후 확정 / `보류` = 다른 화면에 흡수하기로 해서 두지 않음.

## 플로우

```
메인 → 방찾기(준비 중) / 방만들기
  → 캐릭터 선택 → 방(= 대기실, 친구 초대)
  → [방 위 팝업] 게임 설정(방장이 설정, 참가자는 열람: 미션 부여 방법 + 결과 공개 시각)
  → [방 위 팝업] 미션 설정(서로 정해주기) 또는 자동 뽑기(앱이 정해주기) → 방장이 미션 공개
  → [방 위 팝업] 미션 도착(편지) → 방에서 미션 수행(미션 버튼 팝업에서 사진 업로드) → 결과 대기(n시)
  → 결과/시상식 → 결과 공유
```

## 화면 스켈레톤

| 형태 | 화면 | 배경 |
|---|---|---|
| 배경 위 팝업 | 게임 설정, 미션 설정, 미션 도착 (모두 방 화면 위. 단계가 끝나야 닫힘) / 초대, 참여 멤버, 미션 (방 화면의 버튼으로 열고 닫음) | 선명한 배경 |
| 배경 블러 | 메인, 방찾기, 방만들기, 초대장, 투표·시상식·결과 카드, 결과 공유, 오류·로딩 | 흐린 배경 |

- 배경 그림: 미션 수행까지는 `day`, 결과(`/result`)와 결과 공유(`/share`)는 `sunset`. (`SceneBackground`, 각 구간의 `layout.tsx`)
- 방 화면 구성
  - 게임 시작 전: 초대 버튼(방장, 팝업), 참여 멤버 버튼(팝업), 게임 시작 버튼(방장)
  - 미션 공개 후: 위쪽에 내 미션(편지를 연 뒤). 놀이터에는 **제출한 친구만** 보인다(나머지는 미션 중). **제출 n** 버튼(제출 현황 팝업, 공개 범위가 `public`이면 이름 아래에 각자의 미션), 미션 버튼(사진 업로드), 방장만 **결과 공개** 버튼(확인 팝업)
  - 결과가 열리면 미션 도착 팝업과 같은 모양의 닫을 수 없는 팝업이 뜨고, **구경하러 가기** 버튼으로 결과 화면에 간다
- 오류 화면은 맨 아래에 항상 **메인으로 가기** 링크를 둔다. (`ErrorView`)
- 없는 주소는 "페이지를 찾을 수 없어요" 안내와 메인 링크를 보여준다. 말없이 메인으로 보내면 잘못된 초대 링크를 연 사람이 이유를 알 수 없어서 안내를 먼저 보여준다. (`app/not-found.tsx`)

- 방만들기에서는 닉네임과 동물만 정한다. 미션 부여 방법(정하는 주체 / 공개 범위 / 동일·각자)과 결과 공개 시각은 대기실 이후의 **게임 설정**에서 방장이 정한다.
- 게임은 3명 이상일 때만 시작할 수 있다. 그보다 적으면 **게임 시작** 버튼이 흐리게 보이고, 누르면 이유를 안내한다. 누르면 "더 참여할 수 없다"는 확인 팝업이 먼저 뜬다.
- 방에서 방장이 **게임 시작**을 누르면 `status = playing`, `phase = settings`가 되어 모두의 방 화면에 게임 설정 팝업이 뜬다. 이때부터 초대 링크로 참가할 수 없다.
- 게임 설정은 방장만 수정하고(선택하면 바로 저장), 참가자는 실시간으로 현재 설정을 읽기만 한다. 방장이 **설정 완료**를 누르면 `phase = assign`이 된다. 결과 공개 시각이 지금보다 뒤로 정해져 있어야 완료할 수 있다.
- 사진으로 인증한다는 안내는 따로 보여주지 않는다. 별도 `/notice` 화면도 두지 않는다.
- 초대 링크(`/invite/:roomId/:code`)로 들어온 사람은 닉네임과 동물을 고른 뒤 바로 방으로 간다. 인앱 브라우저에서 열렸다면 먼저 기본 브라우저로 옮긴다. (`INVITE.md`)
- 미션 설정은 부여 방식에 따라 달라진다. 앱이 정하면 `phase = assign`이 되는 즉시 방장 화면이 미션을 뽑아 `phase = play`로 넘긴다(`scope = different`면 서로 겹치지 않게). 뽑기 화면은 따로 없고, 실패하면 방장에게 **다시 뽑기**가 보인다. 직접 부여면 `scope = different`는 참가 순서대로 **다음 사람**에게 줄 미션을 각자 적고, `scope = same`은 방장이 모두가 할 미션 하나를 적는다. 모두 정하면 방장이 **미션 공개**를 눌러 `phase = play`로 넘어가고, 그때부터 미션 도착 팝업으로 받은 미션이 보인다. 공개 범위가 `public`이면 멤버(제출 현황) 팝업에서 모두의 미션도 보인다. (`MISSION_ASSIGN.md`)
- 결과는 `Room.resultAt`(n시) 이후에만 열린다. 방장은 그 전에도 방 화면의 **결과 공개** 버튼으로 먼저 열 수 있다. (되돌릴 수 없고, 이후에는 제출할 수 없다. `RESULT_REVEAL.md`)
- 미션 공개 후 **제출 n** 팝업에는 모든 멤버(방장 포함)의 **제출 여부**(제출함 / 아직이에요)가 보인다. 사진은 결과가 열리기 전까지 본인만 볼 수 있다.

## 라우트 표

| 화면 | 경로 | 상태 | 진입 조건 | 허용 Room 상태 / 단계 |
|---|---|---|---|---|
| 메인 | `/` | 확정 | 없음 | - (방만들기, 방찾기. 방찾기는 준비 중 안내만) |
| 방찾기 | `/room` | 확정 | User 있음 | - |
| 방만들기 | `/room/new` | 확정 | User 있음 | - |
| 캐릭터 선택 | `/room/:roomId/character` | 제안 | 방 생성 또는 방찾기로 입장 | `waiting` |
| 초대 참가 | `/invite/:roomId/:code` | 확정 | 초대 링크 (로그인은 익명으로 자동) | `waiting` |
| 방 (= 대기실) | `/room/:roomId` | 확정 | Player로 참가 | 모든 상태. 단계에 맞는 팝업을 띄운다 |
| 게임 설정 | (방 위 팝업) | 확정 | Player (수정은 방장만) | `playing` / `settings` |
| 미션 설정 | (방 위 팝업) | 확정 | Player | `playing` / `assign` |
| 사진 인증 주의사항 | `/room/:roomId/notice` | 보류 | - | 게임 설정과 미션지정 화면 안에서 안내하므로 별도 화면은 두지 않음 |
| 미션 도착 | (방 위 팝업) | 확정 | Player, 편지를 아직 안 연 경우(이 기기 기준) | `playing` / `play` |
| 미션 진행 | (방의 미션 버튼 팝업) | 확정 | Player | `playing` / `play` |
| 결과 대기 | `/room/:roomId/waiting` | 제안 | Player, 미션 제출 완료 | `playing` / `waitResult` |
| 결과/시상식 | `/room/:roomId/result` | 확정 | Player, `now >= resultAt` 또는 방장이 먼저 공개 | `finished` |
| 결과 공유 | `/room/:roomId/share` | 확정 | Player | `finished` |
| 404 | `*` | 확정 | - | - (메인으로 가는 링크) |

## 가드 규칙

1. **User 가드**: 닉네임이 없으면 메인에서 프로필 생성 후 진행한다.
2. **Room 가드**: `:roomId` 하위 경로는 해당 방의 Player여야 접근 가능하다.
3. **상태 가드**: 현재 `Room.status` / `Room.phase`에 맞지 않는 경로는 맞는 경로로 `replace` 이동한다.
4. **결과 시각 가드**: `resultAt` 이전에 결과/시상식·공유로 오면 결과 대기로 보낸다.
5. **단계 팝업**: 방 화면은 `phase`에 맞는 팝업만 띄운다. 게임 설정 수정은 방장만 할 수 있고, 규칙(`rooms` 문서 update는 방장만)이 서버에서도 막는다.
6. **예전 주소**: `/room/:roomId/(lobby|settings|assign|reveal|play)`는 `/room/:roomId`로 보낸다. (`next.config.ts`)

1. 사진 업로드는 미션 진행 화면 안에서 처리하는지, 별도 화면인지.
