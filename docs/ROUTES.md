# 화면 라우팅 (ROUTES)

기획 흐름은 `PLANNING.md`, 데이터는 `DATA_MODEL.md`, 모드는 `MODES.md` 참고.
표의 **상태**: `확정` = 코드(`packages/shared/src/routes.ts`)와 페이지가 있음 / `제안` = 기획 반영을 위해 추가를 제안한 화면, 확인 후 확정 / `보류` = 다른 화면에 흡수하기로 해서 두지 않음.

## 플로우

```
스플래시 → 방찾기 / 방만들기(모드 선택)
  → 캐릭터 선택 → 대기실(친구 초대)
  → 게임 설정(방장이 설정, 참가자는 열람: 모드가 허용하는 미션 부여 방법 + 결과 공개 시각(모드에 따라) + 사진 인증 안내)
  → 미션지정(앱이 뽑기 / 서로 정해주기: 직접 정하기, 사진 인증 안내 포함) → 방장이 미션 공개
  → 미션공개(편지) → 미션 진행(사진 업로드) → 결과 대기(n시)
  → 결과/시상식 → 결과 공유
```

- **방만들기가 모드 선택을 겸한다.** `/room/new` 한 화면에서 1단계로 모드(5종)를 고르고, 2단계로 닉네임·동물을 골라 방을 만든다. 모드는 친구를 초대하기 전에 정해지며 이후에는 바꿀 수 없다. (`MODES.md`)
- 미션 부여 방법(정하는 주체 / 동일·각자 / 공개 범위)과 결과 공개 시각은 대기실 이후의 **게임 설정**에서 방장이 정하되, 모드가 허용하는 값만 고를 수 있다. 모드가 고정한 항목은 읽기 전용이고, 해당 없는 항목은 보이지 않는다. (`/room/new/settings`는 모드별 기본값용으로 남겨 두며 현재 빈 화면이다.)
- 대기실에서 방장이 **게임 시작**을 누르면 `status = playing`, `phase = settings`가 되어 모두 게임 설정으로 이동한다. 이때부터 초대 링크로 참가할 수 없다. 1인모드는 초대 영역이 보이지 않고 바로 시작한다.
- 게임 설정은 방장만 수정하고(선택하면 바로 저장), 참가자는 실시간으로 현재 설정을 읽기만 한다. 방장이 **설정 완료**를 누르면 `phase = assign`이 되어 모두 미션지정으로 이동한다.
  - "모두 같은 미션"을 고르면 "미션을 미리 공개할까요?"는 묻지 않고 전체 공개로 정해진다.
  - 결과 공개 시각은 모드의 정책(`MODES.md`)에 따라 다르다. 정하지 않는 모드(A)는 입력 없이 완료하고, 방장이 정할지 말지 고르는 모드(B)는 정하기로 했을 때만 지금보다 뒤로 정해야 완료할 수 있다.
- 사진으로 인증한다는 안내는 게임 설정 화면에 항상 보이고, 미션지정 화면에서는 `assigner = players`일 때 보인다. 별도 `/notice` 화면은 두지 않는다.
- 초대 링크(`/invite/:roomId/:code`)로 들어온 사람은 닉네임과 동물을 고른 뒤 바로 대기실로 간다. 인앱 브라우저에서 열렸다면 먼저 기본 브라우저로 옮긴다. (`INVITE.md`)
- 미션지정(`/assign`)은 부여 방식에 따라 화면이 달라진다. 앱이 정하면 방장이 **미션 뽑기**를 누른다(`scope = different`면 서로 겹치지 않게). 직접 부여면 `scope = different`는 참가 순서대로 **다음 사람**에게 줄 미션을 각자 적고, `scope = same`은 방장이 모두가 할 미션 하나를 적는다. 모두 정하면 방장이 **미션 공개**를 눌러 `phase = play`로 넘어가고, 그때부터 받은 미션이 보인다. 공개 범위가 `public`이면 공개 후 모두의 미션 목록도 보인다. (`MISSION_ASSIGN.md`)
- 결과는 `Room.resultAt`(n시) 이후에만 열린다. 방장은 그 전에도 미션 진행 화면의 **지금 결과 공개하기**로 먼저 열 수 있다. (되돌릴 수 없고, 이후에는 제출할 수 없다. `RESULT_REVEAL.md`) 결과 공개 시각을 정하지 않은 방(`resultAt = null`)은 방장이 공개해야 열린다.
- 미션 진행 화면에는 모든 멤버(방장 포함)의 **제출 여부**(✅/⏳)가 보인다. 사진은 결과가 열리기 전까지 본인만 볼 수 있다.

## 라우트 표

| 화면 | 경로 | 상태 | 진입 조건 | 허용 Room 상태 / 단계 |
|---|---|---|---|---|
| 스플래시 | `/` | 확정 | 없음 | - |
| 방찾기 | `/room` | 확정 | User 있음 | - |
| 방만들기 (모드 선택 + 닉네임·동물) | `/room/new` | 확정 | User 있음 | - |
| 방설정 | `/room/new/settings` | 확정 | 방만들기 완료 | - |
| 캐릭터 선택 | `/room/:roomId/character` | 제안 | 방 생성 또는 방찾기로 입장 | `waiting` |
| 초대 참가 | `/invite/:roomId/:code` | 확정 | 초대 링크 (로그인은 익명으로 자동) | `waiting` |
| 대기실 | `/room/:roomId/lobby` | 확정 | Player로 참가 | `waiting` |
| 게임 설정 | `/room/:roomId/settings` | 확정 | Player (수정은 방장만) | `playing` / `settings` |
| 미션지정 | `/room/:roomId/assign` | 확정 | Player | `playing` / `assign` (`play` 이후에는 받은 미션을 보여줌) |
| 사진 인증 주의사항 | `/room/:roomId/notice` | 보류 | - | 게임 설정과 미션지정 화면 안에서 안내하므로 별도 화면은 두지 않음 |
| 미션공개 | `/room/:roomId/reveal` | 확정 | Player | `playing` / `reveal` |
| 미션 진행 | `/room/:roomId/play` | 확정 | Player | `playing` / `play` (제출 현황, 방장의 결과 공개 포함) |
| 결과 대기 | `/room/:roomId/waiting` | 제안 | Player, 미션 제출 완료 | `playing` / `waitResult` |
| 결과/시상식 | `/room/:roomId/result` | 확정 | Player, `now >= resultAt` 또는 방장이 먼저 공개 (시각이 없는 방은 방장이 공개해야 열림) | `finished` |
| 결과 공유 | `/room/:roomId/share` | 확정 | Player | `finished` |
| 404 | `*` | 확정 | - | - |

## 가드 규칙

1. **User 가드**: 닉네임이 없으면 스플래시에서 프로필 생성 후 진행한다.
2. **Room 가드**: `:roomId` 하위 경로는 해당 방의 Player여야 접근 가능하다.
3. **상태 가드**: 현재 `Room.status` / `Room.phase`에 맞지 않는 경로는 맞는 경로로 `replace` 이동한다.
4. **결과 시각 가드**: `resultAt` 이전에 결과/시상식·공유로 오면 결과 대기로 보낸다. (`resultAt`이 없으면 방장이 공개하기 전까지)
5. **설정 가드**: `/settings`는 `phase = settings`일 때만 머문다. 시작 전(`waiting`)이면 대기실로, 설정이 끝났으면 미션지정으로 `replace` 이동한다. 수정은 방장만 할 수 있고, 규칙(`rooms` 문서 update는 방장만)이 서버에서도 막는다. 모드(`settings.mode`)는 규칙이 변경을 막는다.

## 열린 질문

1. 사진 인증 주의사항은 게임 설정과 미션지정(`assigner = players`) 화면 안의 안내 카드로 확정했다. 모드 선택이 방만들기(`/room/new`) 안에 들어갔으므로, 방설정(`/room/new/settings`)을 계속 둘지 없앨지.
2. 사진 업로드는 미션 진행 화면 안에서 처리하는지, 별도 화면인지.
3. 모드별로 달라지는 화면(선착순 생존 상태, 무한미션 타이머와 개수 공개, 1인모드 성장 화면)을 어떻게 분기할지. (모드별 플레이는 `MODES.md`의 "한계와 열린 질문" 참고)
